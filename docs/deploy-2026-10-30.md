# Запуск обновления Nexora

## Vercel → Settings → Environment Variables

Задать для Production (и отдельно для Preview при необходимости):

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL вашего проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key `sb_publishable_…` того же проекта |
| `APP_URL` | Полный HTTPS-адрес приложения, без пути |
| `SUPABASE_SECRET_KEY` | Secret key `sb_secret_…` того же проекта; только сервер |
| `AI_PROVIDER` | `xai` для Grok; также доступны `anthropic` и `openai` |
| `AI_API_KEY` | Ключ выбранного провайдера генерации |
| `AI_MODEL` | Для xAI: `grok-4.7` либо другая доступная вашему аккаунту модель Responses API |
| `EMBEDDINGS_API_KEY` | Ключ OpenAI для embeddings |
| `EMBEDDINGS_MODEL` | `text-embedding-3-small` (1536 измерений) |

Необязательные: `SOURCE_SIGNED_URL_TTL_SECONDS=60`, `AI_REQUESTS_PER_HOUR=30`,
`SEARCH_MIN_SIMILARITY=0.3`. Размер файла 25 МиБ и квоты 100 файлов / 500 МиБ
дополнительно ограничены в базе. Уменьшение MAX_UPLOAD_MB ограничит обработку;
увеличение переменных не отменяет лимиты Storage и БД.

Node.js 24; Fluid compute включён, обработчик документов использует до 300 секунд.
Файлы отправляются напрямую в приватный Storage, поэтому не проходят через
лимит тела запроса Vercel Function. После изменения env выполнить Redeploy.
Ключи без `NEXT_PUBLIC_` не добавлять в публичные переменные.

Для xAI ключ из [консоли xAI](https://console.x.ai/) положить в `AI_API_KEY`.
Помощник вызывает `https://api.x.ai/v1/responses` с `store=false`.
`EMBEDDINGS_API_KEY` по-прежнему должен быть ключом OpenAI: индексация и поиск
используют отдельный провайдер. Уже построенные индексы менять при переключении
помощника на Grok не требуется. После смены env выполнить Redeploy.

## Supabase — обязательно до проверки регистрации

1. Применить все отсутствующие миграции из `supabase/migrations` по порядку.
   Новые: `202610300002_knowledge.sql`, `202610300003_source_upload_validation.sql`,
   `20261030210000_optional_email_verification.sql`,
   `20261030220000_source_path_isolation.sql`.
2. Миграцию проверки почты применить **до** отключения Confirm email: она
   сохраняет реальные подтверждения старых аккаунтов. Если Confirm email уже
   был выключен, прочитать исключение в `docs/optional-email-verification.md`.
3. Authentication → Email: выключить **Confirm email**, оставить вход по Email.
   Тогда новые пользователи сразу входят, а подтверждение выполняют из профиля.
4. В URL Configuration задать Site URL и разрешить точные адреса
   `https://<домен>/auth/confirm` и `https://<домен>/reset-password`.
5. Настроить SMTP в Supabase Auth. Шаблон Magic Link должен содержать
   `{{ .ConfirmationURL }}`. SMTP-пароль в Vercel приложению не нужен.
6. Для ранее созданных, но заблокированных пользователей проверить доступ
   через новую Magic Link ссылку из формы входа. Отключение Confirm email само
   по себе не гарантирует разблокировку старых учётных записей.

## Контроль после настройки

Новый аккаунт → сразу «Мои тетради» → профиль с плашкой → реальное письмо →
подтверждение; затем PDF/PPTX → готовый индекс → поиск → ответ с источниками →
вставка на страницу. Проверить второй аккаунт и отказ в доступе к чужой тетради.

Локально проверены автоматические тесты и демо-интерфейс. SQL-тестам нужен
Postgres/Supabase; реальная доставка почты и внешние AI-вызовы требуют настроенного
стенда. Обработка через `after()` ограничена временем функции: при остановке
платформой доступен повтор через 310 секунд; долговечная очередь не подключена.

Справка: [ограничения Vercel](https://vercel.com/docs/functions/limitations),
[длительность функций](https://vercel.com/docs/functions/configuring-functions/duration),
[настройки Supabase Auth](https://supabase.com/docs/guides/auth/general-configuration).
