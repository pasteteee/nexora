# Регистрация и добровольное подтверждение почты

Новый пользователь после регистрации сразу входит в приложение и может создавать тетради. В меню аватара → «Мой профиль» доступны имя и плашка «Подтвердите почту». Кнопка отправляет стандартное письмо Supabase Magic Link. Подтверждение не блокирует работу и не требует дополнительных секретов в Vercel.

## Порядок настройки

1. Применить `20261030210000_optional_email_verification.sql` **до** переключения Confirm email. Миграция сохраняет подтверждения существующих пользователей. Если Confirm email был выключен ранее, не переносите `auth.users.email_confirmed_at` как доказательство владения адресом — удалите блок backfill из миграции перед применением.
2. Supabase → Authentication → Sign In / Providers → Email: выключить **Confirm email**, оставить Email provider включённым. `npm run smtp:configure` теперь также выставляет это значение; SMTP-письма нужны для добровольной проверки и восстановления пароля.
3. Supabase → URL Configuration: Site URL = HTTPS-адрес приложения, Redirect URLs включают `https://<домен>/auth/confirm`, `https://<домен>/reset-password` и соответствующие адреса для локального/preview окружения.
4. Использовать стандартный Magic Link template с `{{ .ConfirmationURL }}`. Письмо открывать в том же браузере, где была запрошена ссылка: PKCE проверяет сохранённый verifier. В другом браузере можно запросить новое письмо из профиля.
5. Если до переключения остались заблокированные неподтверждённые учётные записи, их владельцы могут открыть новую ссылку из формы входа («отправить снова»). Также администратор может разрешить вход через Supabase Auth, оставив `profiles.email_verified_at` пустым до реальной проверки адреса.

`profiles.email_verified_at` хранит отдельное подтверждение: `email_confirmed_at` в Auth после отключения Confirm email означает лишь разрешение входа. Клиент не имеет UPDATE-права на поле проверки. RPC принимает только подписанную Supabase сессию OTP/Magic Link, сверяет текущий email и не принимает телефонные OTP; в этой версии поддерживается только email-авторизация. Смена адреса сбрасывает проверку.

Новые env не нужны. Для Vercel остаются `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` и `APP_URL`; SMTP хранится в Supabase Auth, не в публичных env.

Проверка: регистрация → тетрадь без письма → профиль с плашкой → письмо → callback → отметка о подтверждении; повторно использованная/просроченная ссылка выдаёт понятную ошибку и позволяет запросить новую. Нужна отдельная проверка доставки на развёрнутом стенде с настоящим SMTP.

Справка: [Supabase passwordless email](https://supabase.com/docs/guides/auth/auth-email-passwordless), [PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow), [JWT claims / AMR](https://supabase.com/docs/guides/auth/jwt-fields).
