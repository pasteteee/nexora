# Производительность редактора (спринт 7, карточка #42)

Критерий ТЗ 22: на странице примерно со 100 объектами прокрутка (pan) и перетаскивание
идут без пропуска больше 2 кадров подряд при 60 Гц, средний отклик на действие не больше 200 мс.

## Как замерить

```bash
npm run build
npx next start -p 3100            # без переменных Supabase, демо-режим
npm run perf:board -- --count 120 # ещё есть --cpu 4 (замедлить процессор), --metrics, --trace
```

Скрипт кладёт в localStorage тетрадь со страницей из N виджетов разных типов (текст, формула,
заметка, канбан, таблица, чек-лист, график, схема, код, карточки, тест, дедлайны, таймер),
открывает её в Chromium и меряет кадры через `requestAnimationFrame`:

- прокрутку колесом вниз и вверх;
- перетаскивание виджета за ручку через всю видимую область;
- задержку от ввода символа в тексте до следующего кадра.

Код выхода 0 значит, что критерий выполнен.

## Результаты (headless Chromium 153, 1440×900, 08.11.2026)

| Сценарий | До | После |
|---|---|---|
| 120 виджетов, обычный CPU | 0 пропусков | 0 пропусков, ввод 15 мс |
| 120 виджетов, CPU ×2 | — | перетаскивание: не больше 1 кадра подряд, ввод 24 мс |
| 120 виджетов, CPU ×4 (слабый ноутбук) | перетаскивание: до 9 кадров подряд (569 пропусков), ввод 97 мс | перетаскивание: до 2 кадров подряд (4 пропуска), ввод 33 мс |
| 300 виджетов, обычный CPU | — | не больше 1 кадра подряд, ввод 15 мс |

На CPU ×4 прокрутка теряет до 3 кадров подряд: это отрисовка самой страницы браузером,
она не зависит от нашего кода и была такой же до правок.

## Что сделано

- **Виджеты не перерисовываются все разом.** Рамка виджета и его содержимое мемоизированы,
  а API доски для виджетов стабилен. Ввод в одном тексте и перетаскивание перерисовывают
  только те виджеты, которые изменились или сдвинулись. Содержимое сдвинутого виджета
  не перерисовывается вовсе.
- **Позиция через `transform`.** Виджеты и место вставки двигаются `translate`, а не `top/left`:
  перестройка страницы во время перетаскивания идёт без пересчёта раскладки.
- **Щит на время перетаскивания и изменения ширины.** Прозрачный слой поверх страницы забирает
  указатель: нет hover-эффектов и проверки попадания по сотне виджетов. Раньше на `body`
  включался селектор `*`, и браузер пересчитывал стили всего документа в первый кадр.
- **Поиск места «рядом с виджетом»** сначала отсекает виджеты по колонкам и читает DOM
  только у тех, что под указателем.
- **Курсоры участников** больше не обходят весь DOM на каждое движение мыши, когда
  не находят прокручиваемый блок: поиск не чаще раза в секунду.
- **Высоты виджетов меряются сразу при открытии страницы.** Наблюдатель размеров создавался
  в эффекте уже после того, как виджеты подключились, поэтому при открытии высоты не мерились,
  и высокие виджеты перекрывали соседние, пока что-нибудь не меняло их размер.
- **Оглавление** строится по данным стора, поэтому сразу видит перестановку и новый заголовок.

Сохранение во время перетаскивания уже шло по ТЗ 4.1.1.1: в стор и автосохранение
попадает только итог после отпускания кнопки.
