# Участники, приглашения и публикации (спринт 6)

Карточка Trello #35 «Участники: приглашения, роли, передача владения». Права проверяет
база данных (SQL-функции `security definer` и RLS), интерфейс только скрывает кнопки.

## Роли (Приложение 2 ТЗ)

| Действие | Владелец | Редактор | Наблюдатель |
|---|---|---|---|
| Видеть тетрадь, список участников | да | да | да |
| Видеть e-mail других участников | да | нет | нет |
| Приглашать, менять роли, исключать | да | нет | нет |
| Передать владение | да | нет | нет |
| Выйти из тетради | нет (сначала передать владение) | да | да |
| Создать/отключить публикацию страницы | да | да | нет |

## Приглашения

1. Владелец вводит e-mail и роль. `POST /api/workspaces/:id/invitations` вызывает
   `create_workspace_invitation` от имени пользователя. В базе хранится только SHA-256 токена.
2. Если адрес уже участник, ответ 409 «Пользователь уже является участником».
   Повторное приглашение того же адреса отзывает прежний токен.
3. Письмо уходит через SMTP приложения, если заданы `SMTP_*` (см. [env.md](env.md)).
   Без SMTP или при сбое почты приглашение всё равно создаётся, владелец получает ссылку.
4. Ссылка `/app/invite/<token>` действует 72 часа, принимается один раз и только аккаунтом
   с тем же e-mail. Адрес должен быть подтверждён (`profiles.email_verified_at`): после
   отключения обязательного подтверждения в Supabase это единственное доказательство владения адресом.
5. Страница приглашения показывает причину отказа: отозвано, уже принято, истекло,
   другой адрес, адрес не подтверждён.

## Публикации

`POST /api/publish/:canvasId` создаёт или возвращает активную ссылку `/p/<slug>`,
`DELETE` отключает её. Повторная публикация после отключения выдаёт новую ссылку, старая не
оживает. Страница в корзине и удалённая тетрадь публично не отдаются; восстановление тетради
возвращает её публикации. Публичная проекция `get_published_canvas` не содержит изображений,
источников, путей хранилища, истории ИИ и служебных полей.

## Клиентский API

`import { collab } from "@/lib/collab"`: `listMembers`, `listInvitations`, `invite`,
`revokeInvitation`, `acceptInvitation`, `setRole`, `removeMember`, `leave`, `transferOwnership`,
`getPublication`, `publish`, `unpublish`, `getPublishedCanvas`. В демо-режиме те же правила
выполняются в localStorage, ссылка-приглашение доступна через `demoInviteInbox(email)`.

## Проверка

- `scripts/db-test-local.sh`: все миграции и pgTAP-тесты на локальном PostgreSQL 16
  (нужны пакеты `postgresql-16-pgvector`, `postgresql-16-pgtap`); 004_collaboration — 49 проверок.
- `npm test`: `tests/collab.test.ts` (демо-правила), `tests/collab-api.test.ts` (маршруты).

Локальная база имитирует только схемы `auth`/`storage`. Настоящий Supabase, отправка писем
и вход двумя реальными аккаунтами проверяются на стенде после `supabase db push`.
