## Найдено и исправлено

1. **Открытый редирект после входа (средний).** `/login?next=//evil.example` уводил на чужой
   сайт: проверка была `startsWith("/")`. Теперь `lib/safe-redirect.ts` пропускает только путь
   внутри приложения. 11 случаев в `tests/security.test.ts`, проверено в браузере.
2. **Уязвимые зависимости (низкий/средний).** `npm audit --omit=dev` нашёл KaTeX 0.16.25
   (GHSA-238p-pmpm-9mq7: обход `trust` при загрязнении прототипа) и nodemailer 10.1.2
   (ошибки разбора адресов). Обновлены до KaTeX 0.19.1 и nodemailer 10.1.7, теперь
   `found 0 vulnerabilities`. Адреса для nodemailer и раньше проходили строгую проверку.
3. **Нет заголовков безопасности (средний).** Добавлены в `next.config.ts`: запрет встраивания
   (`frame-ancestors 'none'`, `X-Frame-Options: DENY`), `nosniff`, HSTS, Permissions-Policy,
   `object-src 'none'`, `base-uri`, `form-action`. Полную CSP со `script-src` не включали:
   ей нужны nonce для встроенных скриптов Next.js. Это задача на будущее.
4. **Секрет в адресе уходил в Referer (средний).** Slug публикации и токен приглашения —
   секреты-«ключи» в URL. Для `/p/*` и `/app/invite/*` теперь `Referrer-Policy: no-referrer`,
   `X-Robots-Tag: noindex` и `Cache-Control: no-store`.
5. **Рассылка писем через приглашения (низкий).** Владелец мог отправлять письма Nexora на
   любые адреса без ограничений. Миграция `20261108230000_security_audit.sql`: не больше 20
   приглашений в тетрадь за час, иначе ответ 429.

Найдено и исправлено раньше, в спринте 6 (pgTAP):
- посторонний мог опубликовать страницу из-за сравнения с NULL;
- приглашение принимал аккаунт без подтверждённого адреса;
- публичная ссылка отдавала страницу из корзины.

## Проверено, замечаний нет

- RLS включена на всех 11 таблицах. Удалять тетрадь, передавать владение и вступать
  в тетрадь можно только через функции с проверкой роли. Вставить строку участника напрямую нельзя.
- Токены приглашений хранятся только как SHA-256, колонку `token_hash` клиент не читает.
- Markdown рендерится без HTML (`Markdown.tsx`). Формулы KaTeX рендерятся с `trust: false`.
- Маршруты ИИ, поиска и обработки проверяют участие и роль до платного вызова.
  `ai_requests` хранит безопасное сообщение без ключей (ТЗ 4.2.11).
- Realtime: каналы страницы авторизуются через `realtime.messages` по роли в тетради,
  личный канал `member:<id>` доступен только самому пользователю.

## Остаточные риски и рекомендации

- Полная CSP с nonce для скриптов (Next.js `proxy`).
- Проверить на стенде: настройки Auth (Confirm email выключен, redirect URL), что
  `SUPABASE_SECRET_KEY` и `SMTP_*` заданы только как серверные переменные Vercel, срок JWT.
- Лимит запросов на вход и регистрацию обеспечивает Supabase Auth: проверить его настройки на стенде.
