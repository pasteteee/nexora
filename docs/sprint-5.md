# Материалы, поиск и помощник

## Настройка

Примените миграции Supabase, включая `202610300002_knowledge.sql`.
В Vercel установите серверные переменные:

- `SUPABASE_SECRET_KEY`: secret key того же проекта Supabase (нужен обработчику и журналу; не добавлять `NEXT_PUBLIC_`).
- `AI_PROVIDER`: `anthropic` или `openai`.
- `AI_API_KEY`: ключ выбранного провайдера генерации.
- `AI_MODEL`: доступная вашему аккаунту модель. Значение по умолчанию: `claude-sonnet-4-5` для Anthropic, `gpt-4.1-mini` для OpenAI.
- `EMBEDDINGS_API_KEY`: ключ OpenAI для векторных представлений.
- `EMBEDDINGS_MODEL`: по умолчанию `text-embedding-3-small`, 1536 измерений. Смена модели требует повторной обработки всех материалов.
- При необходимости: `AI_REQUESTS_PER_HOUR=30`, `SEARCH_MIN_SIMILARITY=0.3`.

Поиск, запуск обработки и генерация совместно расходуют почасовой лимит пользователя; лимит резервируется транзакционно до платного вызова. Повторный запуск готового источника возвращает `ready` без повторного построения векторов. Для смены embedding-модели администратор сначала переводит готовые источники в `pending` (через SQL Editor), затем запускает обработку заново.

Node.js: 22.13+ (рекомендуется 24), требуется PDF.js. Не исключайте опциональный пакет `@napi-rs/canvas` из production install.
Публичные ключи Supabase и `APP_URL` остаются необходимыми для обычного приложения.

## Обработка

Оригиналы сохраняются в приватном бакете `nexora-sources`. После загрузки отдельный POST `/api/sources/:id/process` проверяет пользователя, роль и доступ к живой тетради; переводит запись в `processing` и возвращает 202. Next.js `after()` выполняет обработку после ответа. Файл проверяется по фактическому размеру и сигнатуре, PDF извлекается по страницам, PPTX — по слайдам; текст нормализуется и разбивается на фрагменты 1000 символов с перекрытием 150. PDF без текстового слоя получает `requires_ocr`, изображения сохраняются без визуального анализа.

Готовый индекс и статус фиксируются одной транзакцией. Сбой сохраняет оригинал и старый индекс. Пользователь может повторить обработку или удалить материал. Панель обновляет статусы каждые 4 секунды. После аварийного завершения функции задание можно повторно захватить через 310 секунд.

Это фоновая обработка в пределах Vercel Function, а не долговечная очередь: настроен `maxDuration=300`. План хостинга должен поддерживать эту длительность. Если процесс будет убит платформой или документ слишком велик, пользователь повторяет операцию. Для длительных массовых загрузок обработчик нужно вынести в durable worker; размер извлечённого текста ограничен 2000 фрагментами, PDF — 500 страницами, распакованный текст PPTX — 20 МиБ.

## Поиск и ИИ

Поиск использует существующий pgvector RPC: до 5 результатов, косинусное сходство, сортировка по id при равенстве, порог из конфигурации. Все запросы ограничены текущей тетрадью и RLS. Помощник доступен владельцу/редактору. Контекст: до 20 выделенных объектов (не более 3000 символов текста каждого), три ближайших объекта в радиусе 500, вопрос до 2000 символов, до пяти фрагментов. Координаты соседей вычисляются в БД, полный холст провайдеру не передаётся.

Ответ передаётся потоком NDJSON. Пользователь может отменить запрос, вставить черновик отдельным объектом, либо явно подтвердить замену исходного текста. Если исходный текст изменился после запроса, замена отклоняется. Цитаты показываются отдельно от генерации и ведут к приватному оригиналу через авторизованную подписанную ссылку. При отсутствии найденных фрагментов показана отметка об отсутствии опоры на материалы. Изменения обычных объектов и автосохранение не зависят от ИИ.

## Проверка стенда

Автоматические тесты проверяют реальное извлечение PDF/PPTX/TXT, ссылку на страницу/слайд, сигнатуры и размеры, разбиение, ограничения контекста, отказ наблюдателю/чужому холсту, лимиты, поток ответа и безопасный сбой провайдера.

Перед полной приёмкой на настроенном стенде:

1. Два участника одной тетради и посторонний пользователь. Загрузить PDF 10–30 страниц, PPTX 10–20 слайдов, TXT/MD и изображения; проверить статусы и номера страниц/слайдов.
2. Загрузить сканированный PDF; проверить `requires_ocr`, сохранность оригинала.
3. Найти известный факт, сверить top-5 и цитату с оригиналом. Повторить запрос и проверить порядок.
4. Спросить по тетради и выделению, вставить ответ, подтвердить замену, отменить через undo.
5. Отозвать/испортить ключ провайдера: ошибка видна, редактор и автосохранение продолжают работать; после восстановления ключа повторная обработка успешна.
6. Посторонний пользователь и viewer не запускают ИИ/обработку, приватные материалы другой тетради не попадают в поиск/контекст.

Полная проверка реального Supabase, миграций, внешних провайдеров и прав между двумя пользователями требует рабочего стенда и действующих ключей. Локальные тесты с заменой внешних сервисов её не подменяют.
