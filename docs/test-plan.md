# Тест-план Nexora

Актуализирован 13.11.2026 по [карточкам Trello](https://trello.com/b/16FtRQqX/nexora) и актуальной main. Исправленное ТЗ содержит **32 критерия п. 6.2**: ссылки на 33–41 в историческом плане не добавляют критерии приёмки.

## Запуск

Node.js 24, затем:

```sh
npm ci
npm test
npm run test:infra
npm run typecheck
npm run lint
npm run build
npm run check:client-secrets
npx playwright install chromium firefox webkit
npm run test:e2e
```

Playwright сам собирает приложение в .next-e2e и запускает его на 127.0.0.1:3103. Публичные переменные Supabase пусты только у тестового процесса. Браузеры используют отдельные демо-сессии, письма и платный ИИ не вызываются. Отчёты: playwright-report/index.html, test-results/e2e-results.json, скриншоты и traces при ошибках; они исключены из Git.

Отдельный job GitHub Actions запускает Chromium, Firefox и WebKit, сохраняет отчёт даже при ошибке. Публичный viewer проверяется при 390×844 и 412×915 во всех трёх движках. Это не заменяет приёмку установленных Edge/Safari и жестов на настоящем устройстве.

## БД и реальные интеграции

Локальная БД: bash scripts/db-test-local.sh — одноразовый PostgreSQL с pgvector/pgTAP. Облачные проверки запускаются явно:

```sh
npm run test:db:remote
npm run test:storage:remote
```

SQL-запускателю нужны SUPABASE_PROJECT_REF и SUPABASE_ACCESS_TOKEN в игнорируемом .env.smtp.local. Он выполняет pgTAP внутри BEGIN/ROLLBACK, сравнивает историю миграций и остатки тестовых пользователей до/после. Миграции не разворачиваются. Необязательный --include-pending проверяет неприменённые миграции временно внутри той же транзакции.

Второму нужны URL/publishable key в .env.local и предварительная npm run build с этими значениями. Он создаёт четыре уникальных аккаунта (владелец, редактор, наблюдатель, посторонний), тетрадь и файлы. Независимое подтверждение адреса выполняется через подписанный OTP, полученный административным API, **без письма**. Служебный ключ читается в память для подготовки/очистки и не записывается в файлы/отчёты. Права проверяют клиенты пользователей, не административный клиент.

Проверяются приглашения, Realtime, публикация/отзыв, приватный файл, реальные 25 МиБ / 25 МиБ + 1 байт. Созданные объекты удаляются в finally. Отказ Realtime не скрывает результаты независимых проверок Storage; код выхода остаётся неуспешным при любой ошибке. Облачные команды не запускаются обычным CI и не используют реальные пользовательские аккаунты.

## Тестовые данные

tests/fixtures содержит синтетические PDF на 12 страниц, PPTX на 12 слайдов, три PNG и PDF без текстового слоя. Ответы известны: период вымышленной планеты — 42 дня, число станций — 7. Каждый лист имеет уникальный маркер и должен сохранять ссылку на страницу/слайд.

Пересоздание: python tests/fixtures/generate.py (reportlab, python-pptx, Pillow). Обычные тесты Python не требуют. acceptance-documents.test.ts проверяет настоящие файлы и отсутствие выдуманного текста в скане. Облачные аккаунты имеют уникальный префикс nexora-qa-…@example.test и удаляются после прогона.

## Матрица 32 критериев → проверки

«Частично» — проверена часть поведения, а не принята вся функция.

1. Вход/тетради — workflows.spec.ts, local-data, oauth, email-confirmation; настоящие пароль/OTP и RLS — облачный сценарий. Регистрация и доставка почты на развёрнутом стенде отдельно.
2. Тетради, страницы и корзина — local-data, access-regression, purge-trash, pgTAP 001, workflows.spec.ts. Частично: реальное расписание физической очистки не запускалось.
3. Pan/zoom/четыре фона — geometry, editor-store, public.spec.ts. Частично: публичный viewer проверен; документный редактор нельзя приравнять к прежнему свободному холсту.
4. Девять объектов — objects, document, board, materials.spec.ts. Частично: создание каждого обязательного типа в текущем интерфейсе отдельно.
5. Манипуляции объектами — editor-store, board, workflows.spec.ts (дублирование, удаление, undo). Частично: не все сочетания выделения, группировки и размера.
6. Автосохранение/повтор — autosave, upload-navigation, workflows.spec.ts. Ошибка хранения браузера и сетевые отказы адаптера проверяются раздельно.
7. PDF → индекс → поиск — acceptance-documents, knowledge, knowledge-provider. Извлечение проверено; живые embeddings/индекс/поиск требуют ключей.
8. PPTX/цитаты — acceptance-documents, knowledge. Извлечены все 12 слайдов; живая индексация требует ключей.
9. Повтор/удаление при ошибке — knowledge-provider, knowledge-api, purge-trash. Частично: полный облачный маршрут обработки не запущен.
10. Семантические top-5 — knowledge-api, knowledge, SQL/RLS. Качество живых embeddings не проверено.
11. Ask Workspace — knowledge-api, knowledge-provider, ai. Живой провайдер и качество ответа не проверены.
12. Ask Selection — board, knowledge-api, ai. Живой ответ по выделению требует ключей.
13. Вставка ответа без неявной замены — ai, board, document. Полный сценарий с настоящим ответом отдельно.
14. Сбой ИИ — knowledge-provider/knowledge-api; независимое редактирование без настроенного провайдера — materials.spec.ts. Реальный отказ платного сервиса не имитировался.
15. Изменения участников — realtime, облачный транспорт. Визуальная синхронизация реальных браузерных сессий требует стенда.
16. Наблюдатель — workflows.spec.ts, access-regression, pgTAP 001/004, настоящий API.
17. Посторонний — pgTAP 001/004, collab-api, knowledge-api, access-regression, настоящий Storage/HTTP.
18. Приватный файл — environment.test.mjs, pgTAP 001, настоящий Storage/signed URL.
19. Публикация/отзыв — collab, collab-api, pgTAP 004, настоящий HTTP/RPC.
20. Публичная проекция без Sources/истории ИИ — public-view, collab, pgTAP 004, настоящий HTTP/RPC.
21. Экспорт — export, workflows.spec.ts (JSON/PNG/PDF). Выделенная область/Frame и визуальная сверка сложного документа отдельно.
22. 100+ объектов/отклик — npm run perf:board на 120 виджетах. Headless-замер не заменяет калибровку физического экрана 60 Гц.
23. Presence/курсоры/изменения ≤2 с — realtime, облачный сценарий. Сохраняются измерения и первоначальные отказы; единичный успех не доказывает стабильность SLA.
24. Изоляция поиска/ИИ — knowledge-api, knowledge, SQL/RLS. Настоящий платный AI-вызов из двух тетрадей не выполнялся.
25. Секреты — test:infra, security, check:client-secrets, безопасные HTTP-ответы. Операционные файлы/ключи не коммитятся.
26. Документация — deploy.md, env.md, db.md, recovery.md и этот план.
27. Приглашения — pgTAP 004, collab, collab-api, настоящий OTP и повторное принятие. Доставка письма отдельно.
28. Удаление/восстановление — pgTAP 004, purge-trash, access-regression, настоящий доступ к файлу. Физическая очистка по расписанию отдельно.
29. Файловые лимиты — pgTAP 003, objects, knowledge, materials.spec.ts, реальные 25 МиБ / 25 МиБ + 1 байт. Облачный повтор обработки отдельно.
30. Скан/OCR — настоящий скан в acceptance-documents, статусы в knowledge-provider. Полный серверный путь требует стенда.
31. Мобильный viewer — public.spec.ts: три движка, оба размера, загрузка/pan/zoom/нет переполнения. Нативные Edge/Safari и touch/pinch — ручная проверка.
32. Координаты ±100000 — geometry, objects, workflows.spec.ts с перезагрузкой. Pan/zoom текущего документного редактора отдельно.

## Сквозная приёмка и дефекты

Для Приложения 4 использовать развёрнутый стенд: вход → тетрадь/страницы → объекты → PDF/PPTX → поиск → ИИ → вставка → второй редактор/наблюдатель → публикация → анонимный просмотр → отзыв → экспорт → удаление/восстановление. Полный сценарий нельзя закрывать по сумме моков и демо-тестов.

Дефект содержит исходную карточку, критерий, шаги, ожидание/факт, серьёзность, версию и артефакт. В Trello закрываются подтверждённые пункты; зависимости от стенда остаются открытыми. Итог: [протокол 13.11.2026](qa/2026-11-13-report.md).
